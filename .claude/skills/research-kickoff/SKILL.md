# research-kickoff（調査開始オーケストレーション）

## トリガー

「〇〇についての調査を開始して」「〇〇の調査・分析を始めて」など、既存案件に対する調査（特許調査・市場調査）の開始を指示された場合に使う。

## 処理手順

### 1. 対象案件の特定・確認

1. `projects/` 配下（`_template`・`_archive`・`_index.md` を除く）のフォルダ名を、ユーザーの発言に含まれるキーワードと照合する。
2. 一致する案件が1件だけの場合: 「`<案件ID>` プロジェクトを対象に調査を開始してよいですか？」とユーザーに確認し、承認を得てから次に進む。
3. 一致が0件の場合: 該当する案件が見つからない旨を伝え、`project-create` スキルで新規作成するかを確認する。無断でフォルダを作成しない。
4. 一致が複数件の場合: 候補を一覧表示し、ユーザーに選んでもらう。

### 2. status.yamlの事前確認（二重実行防止）

対象案件の `status.yaml` を読み、`patent_research` / `market_research` が既に `done` になっていないか確認する。

- 両方 `done` の場合: 調査は完了済みである旨を伝え、分析（`patent-analysis`）に進んでよいか確認する（このスキルの役割はここで終了）。
- 片方のみ `done` の場合: 完了していない方だけを起動する（もう片方を再実行しない）。
- 両方 `not_started`/`in_progress` の場合: 手順3に進む。

### 3. 特許調査・市場調査の並列起動

Agentツールで以下の2つのサブエージェントを**同一レスポンス内で同時に**起動する（`Agent`は独立した呼び出しを並列実行できるため、1回のツール呼び出しブロックにまとめて発行すること）。

- サブエージェント1（特許調査）: `subagent_type: general-purpose` を使い、「`.claude/skills/patent-research/SKILL.md` を読み、その手順に従って `projects/<案件ID>/` の特許調査を実行し、`01_research/patent/research_output.md` を作成、`status.yaml` の `patent_research` を `done` に更新し、`projects/_index.md` を更新すること」という趣旨のタスクを渡す。
- サブエージェント2（市場調査）: 同様に `subagent_type: general-purpose` で、`market-research` スキルに従って市場調査を実行するタスクを渡す。

各タスクには対象の**案件ID・案件フォルダの絶対パス**を必ず明記する。両方とも `run_in_background`（デフォルトのバックグラウンド実行）のまま並列に投げ、完了通知を待つ。

### 4. 完了待ち・分析への引き継ぎ

両方のサブエージェントからの完了報告を待つ。両方完了したら、対象案件の `status.yaml` を**メインセッション側で**確認し、`patent_research` と `market_research` が両方 `done` になっていることを確かめる。

- 両方 `done` の場合: 分析結果要約の提示と承認を経て `patent-analysis` スキルに進む（CLAUDE.md 5章のレビューゲート方式に従う）。
- 片方が失敗・未完了の場合: 原因（MCP未接続など）をユーザーに伝え、再実行を提案する。

## 備考

- 各サブエージェント（patent-research/market-research）は自分の担当完了時に「もう一方も完了していれば分析に進める」旨を*提案*してくることがあるが、実際に `patent-analysis` を呼び出すかどうかは、並列実行をオーケストレーションしているメインセッション側（このスキル）が判断する。両方のサブエージェントが同時に分析を開始してしまう競合を避けるため。
